# 02 Interview

**Goal.** Ask the owner everything that would change a scene, until the narrative can be written without guessing.
**Produces.** The owner's answers, held in the conversation and in the ledger's open items.
**Gate.** No question is left that would change a scene.

## How to run it

- **One decision per message** when the answer shapes everything after it (the audience, the climax, the voice).
  **Small numbered batches** otherwise, so the owner can answer inline.
- **Name the consequence in every question.** "Two cuts or one? Two means every short-cut shot is also a long-cut shot,
  and the long cut only adds depth."
- **Recommend an option and mark it.** The owner can still pick another.
- **Follow an answer that opens a new area immediately**, instead of saving it for a later batch.
- **Record every "I don't know" as an open item** in the ledger. Open items are shown as open or left out.

## The question bank

Work through it in this order. Skip what kickoff already answered.

1. **What can the code machine reach?** Open internet, internal mirrors or nothing. Decides whether tools install
   there or travel in the kit.
2. **Who watches, and what should they do after?** Offer: people who will build on it; leaders deciding whether to
   fund it; both in one cut; two cuts from one footage. Decides the cuts and how deep the code goes.
3. **What of the source document runs today?** A list built from the document's own sections. Anything half-built is
   shown only as a figure labelled "design", never as a running system.
4. **Which moment does the video build to?** Offer the beats the document supports: the change made live, the error
   caught early, reconfiguration without code, surviving a failure. Recommend one climax and up to two supporting
   beats.
5. **Which code goes on screen, in which cut?** A table of candidates, each with what it proves. The short cut shows
   only code that is also configuration.
6. **Whose voice, generated where?** Local cloned voice, cloud voice, or a human reading the script. Decides the
   hardware and how quickly a changed line can be re-voiced.
7. **Where does the engagement's material live, and how does it travel?** Client material never enters a shared
   repository.
8. **The scenario.** One fixed input whose output flips on a one-value change. The climax changes that value.
9. **Does the short cut need shorter narration for a scene it shares with the long cut?** If so, it becomes a separate
   scene with its own narration that reuses the same takes.
10. **Who reviews drafts, and where?** Decides whether drafts travel back to the author machine.

## Leaving the phase

Present the narrative ([03](03-narrative.md)) for approval. Do not write the script or the shot list until the owner
says the interview is done.
