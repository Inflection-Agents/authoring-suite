# 09 Set review

**Goal.** Catch the faults that only show up across pages, which page-level review cannot see.
**Produces.** A numbered findings list covering the set as a whole, with the pages each finding touches.
**Gate.** The owner has ruled on every finding and said which ones to take.

Run this when a wave of diagrams is done, and again before the set is shown to anyone. Page-level review passes on all
of them and still leaves the set broken: the same service appears under two names, the same idea is drawn twice, and a
term is used on page 4 and defined on page 12.

Build a contact sheet of every page and look at it, then work through the seven checks below. Report findings as a
numbered list with the pages each one touches. Do not fix anything in this phase. The owner says which findings to take.

## 1. One argument

Read the titles in manifest order as a list, then the subtitles in order as one paragraph. State the argument the set
makes, in five sentences. Then mark:

- two pages that could swap places without loss, which means the order is not carrying anything
- a term used before the page that introduces it
- an orphan page with no link to the one before it

## 2. One vocabulary

Every recurring element appears under one name and one id across every page. List every name that appears in more than
one form. List every element that appears on several pages with a different level of detail each time.

## 3. One visual language

Every connector style is used with the meaning the brief fixes. Every kind of box is drawn the same way. The same kind
of content sits on the same canvas at the same scale. Legends explain only what is on their own page.

## 4. Duplication

Two pages that make the same point. For each, say which one to keep and what the other one has that needs moving.

## 5. Gaps

A claim the set depends on and never shows. A container that appears in the container map and never again. An open item
recorded in the facts file that no page mentions.

## 6. Budget

Every page that is over the complexity budget, with how far over. For each, say whether it should be split into an
overview plus a zoom, pruned, or accepted as an exception, and give the reason a reader would accept. An exception the
builder proposes and the owner declares is fine. An exception nobody declared reads as a mistake.

## 7. Mechanical

Run the set check, the consistency check and the self-check across every page. Report what fails, and separately what
fails falsely, with the reason you believe it is false.

Findings about a single page go back through [08](08-page-critique.md). A budget finding that says the set is too big
for its audience goes to [10](10-prune-and-split.md). A checker that produced false failures goes in the audit notes for
[13](13-handback-audit.md).
